# إعداد Firebase لمزامنة الموجّهة الطلابية — وضع التجربة فقط

**الحالة (2026-10-25):** كود الواجهة والمزامنة التجريبية موجود في GitHub؛ لا يوجد مشروع Firebase مربوط حتى تُملأ بيانات المشروع بعد إنشائه. **لا توجد بيانات طالبات مرفوعة إلى Firebase.**

> ممنوع إدخال/نقل أي بيانات مدرسية حقيقية أو أسماء الطالبات قبل موافقة الجهة التعليمية على Firebase ومكان التخزين والصلاحيات والأجهزة. البيانات القديمة تبقى في التطبيق القديم ولا تُرفع إلى GitHub. هذه الخطوات لبيانات وهمية فقط.

## ماذا اخترنا؟

| الخدمة | الاستخدام |
|---|---|
| Firebase Authentication | بريد إلكتروني وكلمة مرور لحساب تجريبي واحد |
| Cloud Firestore (Standard) | السجلات والتحديثات الفورية بين أربعة أجهزة |
| IndexedDB منفصل | حفظ التعديلات التجريبية مؤقتًا حين ينقطع الإنترنت |
| GitHub Pages | عرض **التجربة الوهمية فقط**؛ الكود لا يشمل البيانات |
| Firebase Hosting / نطاق مستقل | بديل لاحق عند الاعتماد، مع مراجعة سياسات تخزين بيانات الطالبات |

لا حاجة إلى Tailscale أو كمبيوتر منزل يعمل دائمًا أو Supabase. وجود كمبيوتر Windows 11 لا يغير تكاليف Firebase.

## ١. أنشئ مشروع Firebase بنظام Spark المجاني

1. افتح https://console.firebase.google.com/ وسجّل الدخول.
2. اضغط **Create a project**، اسم تجريبي مثل `guidance-v2-sandbox`، واترك Google Analytics غير مفعل لأنه غير مطلوب للمشروع.
3. من **Build → Authentication → Get started → Sign-in method** فعّل **Email/Password** فقط.
4. من **Authentication → Users → Add user** أنشئ حسابًا تجريبيًا ببيانات تسجيل دخول مخصصة. **لا تضع كلمة المرور في GitHub أو تشاركها هنا**.
5. انسخ **UID** الخاص بهذا المستخدم (ليس البريد وكلمة المرور).
6. من **Build → Firestore Database → Create database** اختر **Standard** و**Production mode** (لا تستخدم Test mode المفتوح). اختر منطقة قاعدة البيانات وفق سياسة الجهة؛ **هذه خطوة للتجربة الوهمية فقط** قبل اعتماد المنطقة للبيانات الحقيقية.
7. من Project Overview اضغط أيقونة `</>` لإضافة **Web app**، ثم انسخ قيم إعدادات Firebase العامة: `apiKey`, `authDomain`, `projectId`, `appId`.
8. افتح [`firestore.rules`](./firestore.rules)، واستبدل **REPLACE_WITH_TEST_UID** بـ UID نفسه في القاعدة؛ انشر القواعد في تبويب Firestore → Rules، أو باستخدام Firebase CLI بعد التأكد من المشروع المختار. **لا تنشر قواعد مفتوحة**.
9. افتح [`config.js`](./config.js) في المستودع الجديد، وأدخل القيم الأربع العامة و`allowedUid` (UID نفسه)، واترك `mode: 'demo'` و`allowLegacyImport:false` بدون تغيير.
10. بعد نشر التعديل على GitHub Pages افتح **الإعدادات → دخول Firebase** وأدخل البريد وكلمة المرور التجريبيين؛ استخدم أربعة أجهزة لاختبار إضافة السجلات الوهمية وتعديلها.

## ٢. تحقق من الحماية قبل تجربة أربعة أجهزة

- اسم/UID مختلف: يجب ألا يتمكن من القراءة أو الكتابة حتى لو كان مسجلًا في Firebase Auth.
- دون تسجيل الدخول: لا توجد أي صلاحيات Firestore.
- تأكد من وجود المسارات `users/<UID>/students/<id>`, `entries`, `tasks`, `legacy_records` داخل UID؛ لا تستخدم مجموعات عامة للجميع.
- القاعدة تقبل إنشاء سجل بتسلسل مراجعة `revision=1` ورفض كتابة مراجعة قديمة؛ يعدل على جهازين السجل نفسه ثم يظهر تعارض، دون إسقاط تعديل غير مُرسَل.
- إذا فُصل الإنترنت، تظهر حالة محلية ويظل التعديل بانتظار رفعه عند العودة. المزامنة أثناء الإغلاق الكامل للتطبيق ليست مضمونة على iOS.
- السجلات التجريبية المحلية في IndexedDB غير مشفرة حاليًا، لذا يحظر إدخال أي بيانات حقيقية أو سرية حتى تعديل تصميم التخزين المحلي.
- عند تشغيل التطبيق على نطاق `drburghash-sys.github.io` يُشترك الأصل بين مشاريع GitHub Pages لنفس الحساب؛ **غير مناسب لإنتاج بيانات مدرسية حقيقية**. يلزم نطاق مستقل أو Firebase Hosting مع عزل ومراجعة إضافية.

## ٣. فاتورة Firebase

خطة **Spark (بدون إضافة بطاقة دفع)** مجانية ضمن حصتها؛ Firestore Standard مجاني حتى:
- ١ غيغابايت تخزين
- ٥٠٬٠٠٠ قراءة يوميًا
- ٢٠٬٠٠٠ كتابة يوميًا
- ٢٠٬٠٠٠ حذف يوميًا
- ١٠ غيغابايت إرسال شهريًا

قد يتوقف منتج عند تجاوز الحصة المجانية بدلًا من فرض فاتورة إذا بقي المشروع Spark. **النسخ الاحتياطية المُدارة من Firestore وعمليات الاستعادة التلقائية ليست ضمن حصة Spark المجانية**؛ لا تعتبر المزامنة نسخة احتياطية. يجب تصميم نسخ تصدير مستقلة معتمدة والتحقق من الاستعادة قبل الإنتاج.

## ٤. ملفات التحويل

- `firebase-sync.js`: مكتبة Firebase JS v13.1.0، تسجيل الدخول، المستمعات الفورية، رفع التعديلات مع مراجعات السجل، عزل حساب واحدة.
- `config.js`: بيانات الربط العامة *الفارغة*، لا كلمات مرور.
- `firestore.rules`: قواعد `deny-by-default` إلى أن يُستبدل UID التجريبي ونشرها.
- `app.js`: يستخدم Firestore بدل Supabase إذا أصبح Firebase جاهزًا، مع IndexedDB تجريبي منفصل حسب المشروع و UID.
- `migration.html` و `migration.js`: **فحص محلي للملف القديم**، وزر الاستيراد الحقيقي مغلق.
- `cloud.js` و `supabase-*.sql`: ملفات قديمة غير موصولة بالواجهة، أبقيناها مؤقتًا للتاريخ فقط. لا تستخدمها.

## ٥. حدود النسخة الحالية

- الربط المباشر مع Firebase **لم يُختبر على مشروع فعلي** لغياب بيانات مشروع ومستخدم مصرح؛ الاختبار الحالي مراجعة مصدر وسلوك محلي فقط.
- المزامنة التجريبية يمكن اختبارها على أربعة أجهزة بعد إضافة الإعدادات والقواعد.
- التعارض محفوظ محليًا، لكن **واجهة مخصصة لمقارنة نسختين واختيار الدمج** لم تُستكمل.
- لا يوجد بعد نسخ احتياطي أسبوعي تلقائي موثق الاستعادة أو تشفير قوي للتخزين المحلي.
- لا يُسمح بترحيل سجلات الطالبات الحقيقية الآن. لا يكفي تغيير مفتاح `mode` من `demo` في `config.js` للاستخدام الإنتاجي.

**ملاحظة:** عناصر Firebase Web config العامة يجوز ظهورها في كود الويب عادةً؛ أمن البيانات يجب أن يأتي من Authentication وقواعد Firestore وإدارة حسابات الأجهزة، وليس إخفاء `apiKey`.
