# تفعيل Firebase Passwordless — الموجهة الطلابية (نسخة تجريبية)

**المشروع:** `student-guidance2`  
**الحسابات:** مستخدمة واحدة على ٤ أجهزة (جوالان وكمبيوتران).  
**الحالة:** أُضيفت إعدادات Web SDK للتطبيق؛ تم برمجة تسجيل الدخول برابط البريد؛ **لم تختبر المصادقة مع خوادم Firebase ولم تُنشر قواعد Firestore بعد.**  
**المعلومات الحقيقية:** ممنوع رفع بيانات الطالبات أو استيراد النسخة القديمة حتى الحصول على موافقة الجهة المختصة ومراجعة الأمن والنسخ الاحتياطية.

## الخطوات المطلوبة في Firebase Console

1. افتح https://console.firebase.google.com/project/student-guidance2/authentication/providers (إذا تغير المسار: Build → Authentication → Sign-in method).
2. ضمن مزوّد **Email/Password** فعّل **Email/Password** *و* **Email link (passwordless sign-in)**، ثم احفظ. تفعيل الخيار الأول مطلوب من Firebase لتشغيل الثاني، **مع أن الدخول نفسه لن يطلب كلمة مرور**.
3. انتقل إلى **Authentication → Settings → Authorized domains → Add domain** وأضف النطاق فقط:
   `drburghash-sys.github.io`  
   لا تضع `https://` ولا `/student-guidance2` في خانة اسم النطاق.
4. افتح التطبيق التجريبي في المتصفح: https://drburghash-sys.github.io/student-guidance2/
5. من الإعدادات أدخل بريد زوجتك واضغط **إرسال رابط دخول للبريد**.
6. افتح الرابط الوارد في بريدها. إذا فتحته على جهاز أو متصفح مختلف، سيطلب تأكيد **البريد نفسه** مرة أخرى؛ لا يحتاج كلمة مرور.
7. بعد اكتمال الدخول سيعرض التطبيق رمز **UID** للمستخدمة الأولى. هذا الرمز ليس كلمة مرور؛ انسخه وأرسله وحده لاستكمال حصر الوصول.
8. بعد توثيق UID، نضعه في `config.js:allowedUid`، وفي `firestore.rules` بدل `REPLACE_WITH_TEST_UID`، وننشر القواعد بعد مراجعتها.
9. أنشئ Cloud Firestore **Standard** في **Production mode** (وليس وضع Test open)، مع اختيار منطقة تجريبية مناسبة لبيانات وهمية فقط. عند إتمام القواعد واختبارها، نستعمل الأجهزة الأربعة لمزامنة سجلات وهمية.

## ما تم تحديثه في الكود

- `firebase-sync.js` يستخدم `sendSignInLinkToEmail` و`signInWithEmailLink`، دون الاعتماد على `signInWithEmailAndPassword`.
- `config.js` يتضمن `emailLinkUrl` ثابتًا للتجربة على GitHub Pages، وUID غير موجود عمدًا حتى أول تسجيل دخول.
- `app.js` يعرض إرسال رابط الدخول وتأكيد البريد من جهاز مختلف وإظهار UID، ويحظر عمليات المزامنة حين يكون UID غير معتمد.
- `firestore.rules` يمنع جميع العمليات حتى استبدال UID ونشره يدويًا؛ المعرّف في العميل ليس وحده حاجز أمان.
- `migration.js` يمنع ترحيل أي بيانات حقيقية إلى Firebase.
- تبقى السجلات الوهمية فقط مسموحة أثناء الاختبار؛ ويُحظر وضع أسماء أو معلومات الطالبات في GitHub.

## نقاط فنية مهمة

- يجب أن يكون النطاق `drburghash-sys.github.io` ضمن **Authorized domains**، لأنه يستضيف رابط عودة تسجيل الدخول التجريبي.
- Firebase Auth يستطيع إنشاء مستخدمة لأول مرة عند إكمال رابط البريد؛ لا حاجة إلى الضغط على Users → Add user أو تعيين كلمة مرور.
- **رابط الدخول أحادي الاستخدام**: لا تشارك رابط البريد ولا رموزه. يجوز مشاركة UID فقط لتقييد القواعد.
- إعدادات Firebase Web العامة مثل `apiKey` و`appId` ليست كلمات مرور. صلاحية الوصول الفعلية تحددها Auth وقواعد Firestore.
- في الوضع الحالي، تعديلات البيانات المخزنة محليًا في IndexedDB غير مشفرة؛ لذلك يمنع إدخال بيانات حقيقية.
- عند الاستخدام الحقيقي ينبغي الانتقال إلى نطاق مستقل بدل أصل GitHub Pages المشترك بين مشاريع الحساب نفسه، والتحقق من حماية الحساب وسياسات المكان والتشفير والاحتفاظ والنسخ الاحتياطية.
- بعض الروابط المرسلة إلى بريد الهاتف قد تفتح في متصفح بدل أيقونة PWA المثبتة. ادخلي عبر المتصفح نفسه حتى يتم تأكيد البريد، وسنعالج تجربة الأيقونة أثناء الاختبار.

**التكلفة:** Firestore Standard وFirebase Auth متاحان ضمن حصة Spark المجانية للاستخدام التجريبي المحدود. تجاوز حصة Spark قد يؤدي إلى تعليق العمليات حتى تجدد الحصة بدل الفوترة التلقائية. المزامنة ليست بديلًا عن نسخ احتياطية يمكن استعادتها.
