# الموجّهة الطلابية — النسخة الثانية (Firebase تجريبي)

## تحديث التقارير وتسجيل الحالات — ٢٥ أكتوبر ٢٠٢٦

أُضيف إلى المشروع الجديد تحديث **لا يغيّر بيانات Firestore المستوردة ولا يتطلب إعادة الاستيراد**:

- التقارير المعروضة والمطبوعة وCSV: القسم، موضوع الحالة، التفاصيل والملاحظات، الإجراء المدون، وحالة المتابعة.
- يقرأ السجل القديم الأصلي من `legacy_records` باستخدام `source_legacy_id`، لذلك تظهر تفاصيله السابقة دون مسحها أو الكتابة عليها.
- عندما لم يحدد السجل القديم حالة المتابعة، يكتب التقرير «لم تُوثّق حالة المتابعة» لا «مفتوحة» ولا «مغلقة» دون دليل. تسمح نافذة تعديل السجل بتعيينها.
- ملاحظات المواقف اليومية تظهر بوصفها «ورد في ملاحظات السجل القديم»، وليس باعتبارها دائمًا إجراءً محققًا.
- عند تسجيل حالة جديدة، تُكتب حروف من الاسم فتعرض الطالبات المطابقات مباشرةً، مع تحديد المدرسة الحالية.
- إذا لم تكن الطالبة موجودة، يمكن إضافتها مع الصف والفصل من نافذة الحالة نفسها. تحفظ الطالبة والحالة محليًا في معاملة واحدة ثم تُرسلان إلى قائمة المزامنة؛ يُرفض تكرار اسم مطابق ضمن المدرسة نفسها.
- يمكن تعديل الحالات القديمة متعددة الأسماء التي لم ترتبط بملف طالبة دون إنشاء ملف غير صحيح.

**حالة النشر:** الشيفرة موجودة في GitHub، لكنها لا تظهر على موقع Firebase Hosting حتى إعادة النشر. من Cloud Shell الذي سبق أن نُشر منه الموقع:

```bash
cd ~/student-guidance2 && git pull && bash deploy-firebase-hosting.sh
```

**لا تعيدي استيراد الـ٩٨ سجلًا.** تكفي إعادة نشر ملفات الواجهة. راجعي تقرير مدرسة ابتدائية وتقرير مدرسة متوسطة ثم اختبري بحث الطالبة الجديدة على الجهاز. لا تشاركي صور حالات الطالبات الصحية مع بيانات التعريف في الدردشة.

**ملاحظة أمان:** التنزيل المحلي لملفات JSON الحالية ليس نسخة احتياطية سحابية مُدارة مشفّرة أو مختبرة الاستعادة؛ يلزم إكمال خطة النسخ الاحتياطية وتدقيق صلاحيات البيانات قبل اعتبار النظام إنتاجيًا.

## الخيار النهائي للمزامنة

اختير **Firebase Authentication + Cloud Firestore**؛ لا نستخدم Tailscale أو كمبيوتر المنزل كخادم أو Supabase. أربع أجهزة للمستخدمة نفسها: جوالان وكمبيوتران. لا تحتاج إلى كمبيوتر مفتوح طوال الوقت.

- `firebase-sync.js`: مصادقة Firebase، تحديثات لحظية عبر Firestore ورفع طابور التعديلات التجريبية.
- `firestore.rules`: لا تعمل صلاحيات القراءة والكتابة حتى وضع UID المستخدم التجريبي المحدد ونشر القواعد.
- `config.js`: لا توجد بيانات مشروع Firebase بعد. إعدادات Web العامة اللازمة لربط المشروع فارغة.
- `app.js`: تطبيق تجريبي مستقل يعرض المدرستين `p31` و`m34`، وملفات الطالبات والمهام والمواقف والتقارير.
- `migration.html` و `migration.js`: فحص محلي لنسخة JSON القديمة وتوزيع السجلات بين المدرستين، **النقل السحابي الحقيقي معطل**.

## سلامة بيانات الطالبات

- **لا ترفع أي سجل حقيقي إلى Firebase أو GitHub الآن.** المشروع التجريبي لا يملك موافقة الجهة المعنية على الاستضافة والتخزين الخارجي.
- البيانات المرسلة في محادثة سابقة خاصة بالمدارس لا توجد داخل هذا المستودع ولا ضمن ملفات التجربة.
- SQLite / Tailscale / Supabase لم تعد جزءًا من المسار المعتمد؛ أزلت ملفات نموذج Supabase غير المستخدمة من المستودع الجديد؛ تبقى التغييرات السابقة في سجل Git التاريخي.
- GitHub Pages صالح لتجربة بيانات وهمية فقط. لا تضع بيانات الطالبات على صفحات مشتركة الأصل أو في `localStorage` / IndexedDB غير مشفر.
- لا يُفترض أن قواعد Firebase تحل وحدها اشتراطات الموافقات التنظيمية والتشفير المحلي وإدارة النسخ الاحتياطية؛ الإنتاج يحتاج مراجعة مستقلة.
- لا تكتب كلمات المرور أو مفاتيح `service account` داخل `config.js` أو الرسائل.

## الوظائف الحالية

- الواجهة الكحلية والذهبية، والمدرستان منفصلتان في الفلاتر وعرض السجلات.
- إنشاء/تعديل ملف طالبات تجريبي ومواقف ومهام.
- معاينة وطباعة تقارير، تصدير JSON وCSV للتجربة.
- حساب Firebase الواحد وقواعد `firestore.rules` تم إعدادهما داخل Firebase بحسب تأكيد المستخدم؛ الاختبار الفعلي للمزامنة بين الأجهزة والترحيل لم يكتمل.
- معالجة تعديلين متعارضين تتم حاليًا برفض التحديث المختلف والاحتفاظ به محليًا، لكن شاشة الدمج التفصيلية قيد التطوير.
- النسخ الاحتياطي الآلي والاستعادة، والتحقق من تشفير البيانات على الأجهزة الأربعة، وتعميم استخدام البيانات الحقيقية غير مكتملة بعد.
