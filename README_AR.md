# الموجّهة الطلابية — النسخة الثانية (تجربة مستقلة)

تاريخ: 25 أكتوبر 2026. نسخة تجريبية ببيانات وهمية، مبنية على إجابات استبيان التطوير في Google Forms؛ لا تُعد إصدارًا إنتاجيًا مؤمّنًا للاستخدام مع بيانات طالبات حقيقية.

## مهم جدًا

- النسخة القديمة في `drburghash-sys/student-guidance` لم تُعدل، ولم يجر نقل أي سجلات منها.
- يحتوي المشروع على واجهة كاملة قابلة للتجربة مع أيقونة مدمجة، سجل الطالبات والمهام والمواقف، لوحات مؤشرات، طباعة/حفظ PDF عبر المتصفح، وتصدير CSV وJSON.
- تتضمن النسخة **إطار مزامنة اختياريًا** عبر Supabase: الاتصال غير مفعل حتى تحديد الخدمة وموقع تخزين البيانات ومراجعة ضوابط الحماية وإنشاء قاعدة البيانات وتسجيل دخول مصرح به.
- **لا تدخل بيانات طالبات حقيقية في وضع التجربة المحلي**. قد تُحفظ بيانات المتصفح دون تشفير وقد تُحذف عند تنظيف المتصفح.

## فتح التجربة

1. افتح المشروع عن طريق خادم محلي بسيط (مثل `python -m http.server 8000`) أو استضافة HTTPS مستقلة عن الموقع القديم.
2. افتح `http://localhost:8000`، وستظهر سجلات وهمية لإظهار الواجهة. 
3. جرّب المدرستين، وأضف طالبة وهمية وحالة وهمية واطبع تقريرًا.
4. الأيقونات في `/icons` وبيانات التثبيت في `manifest.webmanifest`.

## ما تقرر وفق الاستبيان

- بطاقة رئيسية كحلية/ذهبية ولوحة مؤشرات، وبطاقات خدمات كبيرة.
- مدرسة ابتدائية 31 ومدرسة متوسطة 34؛ فصل السجلات بكل مدرسة.
- تسجيل الدخول لموجّهة واحدة بأجهزتها المختلفة عند تفعيل المزامنة، والكتابة دون اتصال ثم الإرسال عند عودته.
- ملف موحد للطالبة، تصفية وسجل مهام، تقرير شهري ورسوم، معاينة قبل الطباعة وCSV/JSON.
- إظهار أسماء الطالبات في التقارير خيار غير مفعّل افتراضيًا.

## تفعيل المزامنة لاحقًا بعد الموافقات

1. الحصول على موافقة الجهة المسؤولة عن بيانات الطالبات وتحديد موقع الاستضافة المعتمد؛ تطبيق متطلبات الحماية والاحتفاظ والنسخ الاحتياطي والتشفير والصلاحيات.
2. إنشاء مشروع Supabase في بيئة تجريبية **ببيانات وهمية فقط** واستخدام ملف `supabase-schema.sql` لمراجعة بنية القاعدة؛ الملف قابل لتجربة أولية، ولم يمر بعد بمراجعة أمنية إنتاجية.
3. إنشاء مستخدم مخصص للنسخة التجريبية عبر Supabase Auth (Email/Password). لا تعطي المستخدمات مفتاح `service_role`، ولا تضعه في الويب مطلقًا.
4. قبل تمكين الاتصال بعد تجربة محلية، امسح بيانات موقع النسخة التجريبية أو استخدم عنوان نشر مستقل جديد لمنع اختلاط السجلات الوهمية بالحقيقية. ثم املأ `config.js` بمفتاح Supabase العام `anon`/`publishable` وURL فقط، والنشر على نطاق HTTPS تجريبي منفصل. المزامنة تتم من القائمة «الإعدادات». تأكد من تشغيل سياسات RLS والاختبارات بعزل حسابين.
5. انتبه: خاصية اختيار «آخر تعديل يحل محل السابق مع سجل للتعديلات» مطبقة على مستوى حفظ آخر سجل في القاعدة وتدقيق تحديثه، لكن معالجة التعارضات المتزامنة وتشفير مخزن الجهاز يلزمان اختبارًا وتطويرًا إضافيًا قبل الاستخدام الحقيقي.

## العناصر المحجوزة للإصدار الإنتاجي

- الحماية الكاملة لجهاز غير موثوق، دعم تسجيل الخروج ومسح ذاكرة الطالبات، وإجراءات مراجعة صلاحيات الدخول.
- مرفقات محمية، نماذج تواصل أولياء الأمور، المهام والتنبيهات الآلية على مستوى الخادم، تدقيق مرئي داخل الواجهة، نسخ أسبوعية مجدولة إلى وجهة مستقلة، واستعادة موثقة.
- استيراد النسخة القديمة يتم **في النهاية** عبر مرحلة فرز وتطابق حقول، واستيراد تجريبي، ومقارنة عدد سجلات وتدقيق العينات قبل اعتماد النقل.

## ملفات المشروع

- `index.html`, `styles.css`, `app.js`: التطبيق التجريبي.
- `cloud.js`, `config.js`: الاتصال الاختياري بخدمة المزامنة.
- `supabase-schema.sql`: مخطط اختباري لقاعدة البيانات وسياسات RLS وتاريخ التعديلات.
- `manifest.webmanifest`, `service-worker.js`, `icons/`: تثبيت الأيقونة والعمل دون اتصال للواجهة.
